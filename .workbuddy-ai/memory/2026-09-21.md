# 2026-09-21

## The profile gate is tripped by the app's own `:sound` editor

Asked to "invalidate all merge tasks". Investigated instead of acting, and the
request turned out to be a no-op for a reason nobody had named.

**State found.** `workspaces/beyond-myriads/ledger.json`: 400 tasks — crawl 100
done, digest 100 done, render 100 done, **merge 100 pending**, every one
`detail: "requeued: sound design changed"`, `attempts: 0`, `assigned_to: null`,
`lease_until: null`, 100 distinct `design` stamps. `output/` holds only
`.DS_Store`. `data/audio/segments-vieneu-{01..100}` all present. So the library is
**already fully invalidated with the render cache intact** — `:remerge`
(`op_remerge_all`, "requeue every merge — render cache kept, no confirm") would
report 100 requeued and change nothing.

**Why.** One `:sound` edit at 21:52:32 — `assets/inject-pool.json`, entry
`cooking`, `level` 0.8 → 0.2. That single write did two things:

1. `tui/sound.rs::save` → `audio_pool::save_pool` rewrote `assets/`, so the live
   tree no longer hashed to `.bm/profile`. The daemon now dies at startup:
   `live assets + prompts do not match profile 'xianxia' (hash drift …)`
   (`bm-core/src/profile.rs:210-225`), 6 attempts in the log tail, nothing on
   `127.0.0.1:8901`. The TUI (pid 78328) is alive but has no backend.
2. `Op::SoundChanged` → `invalidate_stale_design(adopt=false)` requeued **all
   100** merges and deleted their mp3s. Not because the edit was wide — `cooking`
   is placed by **4** chapters (9, 19, 36, 99) — but because `adopt=false`
   requeues every `Done` merge whose stamp is `None`, and the whole library
   predated the stamp field.

**Proof of the drift.** Unpacked `profiles/xianxia.tar.zst` to a temp dir and
diffed manifests: pointer `b20f7789f510…` == bundle == `manifest.json`, live tree
`09e9a6ed4ba1…`, 101 files both sides, **exactly one** differing —
`assets/inject-pool.json`. Nothing added, nothing removed.

**The repair, and the trap in the error message.** The gate's own suggested fix,
`profile load xianxia`, is `rm -rf assets prompts` + re-extract the 06:25 bundle —
it would silently revert `cooking` to 0.8. `profile.sh pack` re-bundles the live
tree but does **not** write the pointer. Correct order is both:
`:profile pack xianxia` then `:profile xianxia` (or
`tools/profile.sh pack xianxia && tools/profile.sh unpack xianxia`), cluster
stopped. Not run — it rewrites a local bundle and is the operator's call.

## Facts worth keeping

- **The mix is applied at merge, not render.** `assemble()` calls
  `ambience::injects_of`, so effect/inject/music layers land when segments are
  assembled. A mix change needs merges only; `invalidate_render` would delete the
  stochastic TTS provenance in `segments-*/` for nothing.
- Script sound directives are **their own segments** — `{"sound": "coin"}` — not a
  `sounds` array on a segment. 219 placements over 28 distinct sounds.
- Merge `affinity` is spread across the 4 boxes (192.168.2.2 ×29, 18.192.121.19
  ×25, 63.178.246.198 ×25, 127.0.0.1 ×21), and remote merges fail with "N segments
  missing" because the segment cache is local; `localhost-caracal` then succeeds on
  retry.
- `.workbuddy-ai/` was **absent** on re-check this session (it was present at the
  first `ls`). Recreated with a consolidated `MEMORY.md`; the daily logs that lived
  there are lost — `.workbuddy-ai/` is untracked, so there is no git history to
  recover them from.
